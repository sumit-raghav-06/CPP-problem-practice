**2. Conceptual Analysis: What, Why, and How**

**WHAT is the problem asking?**

**The problem requires building arrays of length n using values strictly chosen from the inclusive
range [l, r]. The primary constraint dictates that adjacent elements must strictly alternate
directions, forming a "ZigZag" shape. There are exactly two foundational skeletal structures that
satisfy this criterion:**

**1. Increasing First: x0 < x1 > x2 < x3 > ...**
**2. Decreasing First: x0 > x1 < x2 > x3 < ...**


**Due to total algebraic symmetry, the total number of valid configurations generated by the
Increasing First pattern is identical to the count generated by the Decreasing First pattern.
Therefore, we can compute the answer for a single structure and multiply the final result by 2.
WHY use Dynamic Programming instead of Brute Force?**

● The current array index i (which dictates whether the next step must move up or down).

**This localized dependency allows us to compress states into a dynamic programming table.
HOW do we solve it efficiently?**

**Let M = r - l + 1 represent the total count of valid choices. We can shift our native boundaries
from [l, r] to a clean zero-indexed tracking boundary of [0, M - 1]. We maintain a DP array dp[j]
representing the number of valid sequence prefixes that end with the specific value j**

3.**Mathematical Transitions and Optimization**

During each transition from state i-1 to state i, we re-evaluate the array constraints. If the
transition requires an upward slope (increasing relationship), the new state is defined as:
new_dp[j] = Sum over k from 0 to j-1 of (dp[k])

**Conversely, if the transition requires a downward slope (decreasing relationship), the new state
is defined as:**

**new_dp[j] = Sum over k from j+1 to M-1 of (dp[k])
Computing these sums naively requires iterating through previous values, resulting in an inner
loop of O(M) and an unacceptable overall complexity of O(n × M2). By introducing a running
sum variable that updates alongside our primary iteration loop, we instantly convert the sum
into an O(1) operation, making the complete runtime a clean O(n × M).**
